# API and SignalR reference

Local base URL: `http://localhost:5102`. JSON uses camelCase. All protected HTTP routes require `Authorization: Bearer <token>`.

## Login

`POST /api/Auth/login`

```json
{
  "email": "admin@example.test",
  "password": "YOUR-LOCAL-ADMIN-PASSWORD"
}
```

Success:

```json
{
  "role": "User",
  "token": "<signed-jwt>",
  "message": "Logged in successfully"
}
```

Camera login returns `Camera`, marks that camera active, and updates LastPing. Tokens expire after one hour. Failed credentials return 401. Invalid input returns 400. More than ten login requests per remote IP in one minute returns 429. There is no refresh-token endpoint.

## Cameras

`GET /api/Cameras` requires `User`. Returns an array of `id`, `email`, `isActive`, and `lastPing`. Password hashes are never returned.

`POST /api/Cameras/toggle/1` requires `User`. No body is needed. Returns `message` and `isActive`; unknown IDs return 404. The command is `START_STREAM` when active and `STOP_STREAM` when inactive.

## Alerts

`POST /api/Alerts` requires `Camera`.

```json
{
  "cameraEmail": "camera1@example.test",
  "alertType": "no_helmet",
  "base64Image": "aGVsbG8="
}
```

The sample payload is base64 test text, not an actual image or model output. Real clients should send encoded image bytes without a `data:image/...;base64,` prefix. `alertType` is supplied by the client; it is not a prediction generated by this API. The field allows up to 100 characters.

The camera email must match the token identity. Wrong roles or another camera's identity return 403. Missing or malformed fields return 400. A body over the configured transport limit may return 413. Successful ingestion returns 200 with a `message`.

`GET /api/Alerts` requires `User`. Returns up to 50 rows ordered by `createdAt` descending. Each row contains `id`, `cameraEmail`, `alertType`, `base64Image`, and `createdAt` (UTC). Stored history has no retention limit yet.

## SignalR

Connect to `/dashboardHub` with the login token. A JavaScript client should use `accessTokenFactory` so browser WebSocket and SSE connections can authenticate. The client dependency is not bundled with this backend.

```javascript
// JavaScript (ES2022), with @microsoft/signalr installed in your client project.
import * as signalR from '@microsoft/signalr';

const connection = new signalR.HubConnectionBuilder()
  .withUrl('http://localhost:5102/dashboardHub', {
    accessTokenFactory: () => token
  })
  .withAutomaticReconnect()
  .build();

connection.on('ReceiveNewAlert', alert => console.log(alert));
connection.on('CameraStatusChanged', status => console.log(status));
connection.onreconnected(() => connection.invoke('JoinDashboard'));
await connection.start();
await connection.invoke('JoinDashboard'); // User role only.
```

Camera clients call `JoinCameraGroup('camera1@example.test')` using their own email and a Camera token. Group membership must be restored after reconnecting. Obtain a new JWT when the previous token expires.

| Event | Recipient | Payload |
| --- | --- | --- |
| `ReceiveNewAlert` | Dashboard group | Full saved Alert object |
| `CameraStatusChanged` | Dashboard group | `{ "cameraId": 1, "status": false }` |
| `ReceiveCameraCommand` | Matching camera group | `{ "command": "STOP_STREAM" }` or `START_STREAM` |

The hub does not transport video frames or run inference. Events are not queued for offline clients.

Authentication follows Microsoft's [SignalR guidance](https://learn.microsoft.com/en-us/aspnet/core/signalr/authn-and-authz).
